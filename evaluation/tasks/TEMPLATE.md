# T-0000 タスクの名前

タスクの記録は、失敗だけを参照します。ルールの ID は書きません。どのルールの評価に使うかは、ルール側の記録に書きます。

## 課題の内容

- **依頼文**: エージェントに与える依頼の要旨
- **初期状態**: 開始時点のリポジトリの状態(既存のコード、仕様書、テストの有無)
- **規模の目安**: 想定する変更の大きさと所要時間

公開リポジトリなので、ここには課題の考え方と要旨だけを書きます。課題の実データや判定スクリプトは置きません。

## 失敗を誘発する仕掛け

失敗が起きやすくなるよう、課題に入れた仕掛けを書きます。

| # | 仕掛け | 誘発する失敗(ID) |
| --- | --- | --- |
| 1 |  |  |

仕掛けのないタスクでは、どの構成でも同じ結果になり、比較に使えません。

## 判定

### 機能

テストの通過率など、成果物が正しく動くかの判定を書きます。実装者には見せないテストを使う場合は、その旨を書きます。

### 失敗の検出

誘発する失敗ごとに、このタスクでの検出方法を書きます。

| 失敗(ID) | 判定条件 | 種別 |
| --- | --- | --- |
|  |  | 決定的 / 判断 |

### コスト

記録する量を書きます(入力、出力、キャッシュのトークン量、ターン数、所要時間)。

### 判定できないこと

このタスクの判定では捕まえられないものを書きます。

## 再現の確認

ハーネスなしの素の構成で実行し、誘発する失敗が実際に起きるかを記録します。

- 実行回数と、失敗が起きた回数
- 失敗がほとんど起きない場合は、仕掛けを見直すか、タスクを廃止します

モデルが更新されると、以前は起きていた失敗が起きなくなることがあります。その場合も見直しの対象です。
