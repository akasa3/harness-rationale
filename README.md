# harness-rationale

コーディングエージェント向けカスタムハーネスを、新規に作るとき・更新するときの「なぜ」を記録するリポジトリです。

ハーネスそのもの(ルールファイル、hook、スクリプト)は置きません。置くのは、ルールを採用する理由、外す理由、その判断の根拠です。

## なぜ記録するのか

ハーネスのルールは、放置すると増える一方になります。理由が記録されていないルールは、後から外してよいか誰にも判断できないからです。

ここでは各ルールについて「何の失敗を防ぐためか」「その失敗はまだ起きるか」「別の手段で防げていないか」を問える状態を保つことを目指します。

## 構成

| パス | 内容 |
| --- | --- |
| [`principles/`](principles/) | 根本にある思想。1件1ファイル |
| [`taxonomy.md`](taxonomy.md) | ルールの分類軸と、分類から置き場所を決める対応表 |
| `rules/` | ルール1件ごとの記録(防ぎたい失敗、判定方法、採否の根拠)。今後追加 |
| `decisions/` | 採否の判断記録。今後追加 |
| `evaluation/` | 評価指標とベンチマーク設計の考え方。今後追加 |
| [`references.md`](references.md) | 参照した論文・記事 |

## 読み方

- まず [`principles/`](principles/) を番号順に読むと、全体の考え方が分かります。
- 個々のルールをどこに置くかは [`taxonomy.md`](taxonomy.md) を参照してください。

## 前提と範囲

- 対象はコーディング領域のエージェントで、主に Claude Code を想定しています。
- 記述は特定時点のモデルとツールを前提にした考えです。モデルが更新されれば結論が変わりうるので、各記録には前提にした時期を残します。
- 外部の研究や記事に基づく記述には出典を付け、筆者自身の考えや未検証の推論とは区別して書きます。
